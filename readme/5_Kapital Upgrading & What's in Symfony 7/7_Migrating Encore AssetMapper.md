## 🔄 Migrating Encore -> AssetMapper / Encore’dan AssetMapper’a Geçiş

Symfony 6.3 ile birlikte `AssetMapper` adlı yeni bir bileşen geldi... ve bayıldım! Tamam, üzerinde çalışıyorum... yani tamamen objektif değilim... ama bana güvenin, harika! Artık modern JavaScript ve CSS’i hiçbir derleyici olmadan yazmamızı sağlıyor. Bunun için bir `Asset Mapper` eğitimi ve daha yeni bir `LAST Stack` eğitimi de var.

## ⚖️ AssetMapper Vs Webpack Encore? / AssetMapper mı, Webpack Encore mu?

`AssetMapper`, `Webpack Encore`’un yerini alan bir bileşendir. Encore yakın zamanda ortadan kalkmayacak ama emeklilik broşürlerine baktığını gördüm!

Muhtemelen şunu merak ediyorsunuz:

`Webpack Encore`’dan `AssetMapper`’a geçmeli miyim?

Kısa ama çok tatmin etmeyen cevap: karar size kalmış. `AssetMapper` daha modern, kullanımı kolay ve Encore’daki yavaş derlemelerden bıktıysanız geçmek için harika bir sebep. Ama Encore sorunsuz çalışıyorsa, AssetMapper’a geçmek için büyük bir neden yok. Ayrıca React veya Vue kullanıyorsanız, hala derleme adımına ihtiyaç duyduğunuz için Encore ile devam etmelisiniz.

## 🧹 Removing Webpack Encore / Webpack Encore’u Kaldırmak

Ama hadi geçiş yapalım! Terminalde, `yarn watch` çalışan sekmeyi bulun. `Ctrl+C` ile durdurun ve o sekmeyi kapatın. Artık bir derleme sistemine ihtiyacımız yok – ikinci sekmeye gerek kalmadı.

Sonra şunu çalıştırın:

```
composer remove symfony/webpack-encore-bundle
```

👉 Bu komut, `symfony/webpack-encore-bundle` paketini kaldırır ve ilgili tarif de kendini temizler.

Paket silinir; daha da önemlisi: tarifi kendi kendini kaldırır! Çok iyi: `package.json` yok, `webpack.config.js` yok, `base.html.twig` içindeki `encore_entry_` fonksiyonları yok.

Ama... `app.js` ve `app.css` dosyalarını da sildi. Bu dosyaları istiyoruz, o yüzden şu komutu çalıştırın:

```
git checkout assets/
```

👉 Bu komut, `assets` klasöründeki silinen dosyaları geri getirir.

Diğer her şey iyi görünüyor! Şunu çalıştırın:

```
git diff
```

👉 Bu komut, yapılan değişiklikleri gösterir.

Eski `package.json` içindeki bağımlılıklar `Webpack Encore` ile ilgiliydi ve bunlara ihtiyacımız yok. Ancak bazıları frontend için gerekliydi ve bunları `AssetMapper` ile yeniden ekleyeceğiz.

Değişiklikleri commit edin... ardından `node_modules`, `public/build/` ve yarn hata dosyasını silerek kutlama yapın. Ayrıca `yarn.lock` dosyasını da silebiliriz. Harika!

## 🚀 Installing AssetMapper / AssetMapper’ı Kurmak

Şimdi `AssetMapper`’ı kuralım:

```
composer require symfony/asset-mapper
```

👉 Bu komut, `symfony/asset-mapper` paketini yükler.

Tarifi pek çok ilginç şey yapar. AssetMapper’ın nasıl çalıştığına fazla girmeyeceğiz – bunun için başka eğitimler var – ama neler olduğuna bakalım. `.gitignore` dosyasında:

```
.gitignore
// ... lines 1 - 10
###> symfony/asset-mapper ###
/public/assets/
/assets/vendor
###< symfony/asset-mapper ###
```

👉 Bu satırlar, oluşturulan asset’lerin ve vendor dosyalarının son konumunu `.gitignore` ile hariç tutar.

Ve `templates/base.html.twig` dosyasında, CSS ve JavaScript çıktısı için bir `importmap()` fonksiyonu eklendi.

```
templates/base.html.twig
// ... line 1
<html>
    <head>
// ... lines 4 - 9
        {% block stylesheets %}
        {% endblock %}
        {% block javascripts %}
{% block importmap %}{{ importmap('app') }}{% endblock %}
        {% endblock %}
    </head>
// ... lines 17 - 82
</html>
```

👉 Bu ekleme, `importmap()` fonksiyonu ile JS/CSS asset’lerini yükler.

Ayrıca bize bir `importmap.php` dosyası verdi:

```
importmap.php
<?php
/**
 * Returns the importmap for this application.
 *
 * - "path" is a path inside the asset mapper system. Use the
 *     "debug:asset-map" command to see the full list of paths.
 *
 * - "entrypoint" (JavaScript only) set to true for any module that will
 *     be used as an "entrypoint" (and passed to the importmap() Twig function).
 *
 * The "importmap:require" command can be used to add new entries to this file.
 *
 * This file has been auto-generated by the importmap commands.
 */
return [
    'app' => [
        'path' => './assets/app.js',
        'entrypoint' => true,
    ],
    '@hotwired/stimulus' => [
        'version' => '3.2.2',
    ],
    '@symfony/stimulus-bundle' => [
        'path' => './vendor/symfony/stimulus-bundle/assets/dist/loader.js',
    ],
    '@hotwired/turbo' => [
        'version' => '7.3.0',
    ],
];
```

👉 Bu dosya, 3. parti paketlerin merkezi haline gelir (yeni `package.json`). Stimulus ve Turbo da otomatik eklenmiş durumda!

Bunlar çalışıyor mu? Sayfayı yenileyin ve... biraz çalışıyor? Bootstrap CSS yok... bu yüzden görünüm kötü. Ama `assets/styles/app.css` yüklendi: temel stiller var. Fakat import’ları düzeltmemiz gerekiyor.

```
assets/styles/app.css
@import '~bootstrap';
@import '~@fortawesome/fontawesome-free/css/all.css';
@import '~@fontsource/roboto-condensed';
// ... lines 4 - 40
```

👉 Bu dosya, üçüncü parti CSS kütüphanelerini import etmeye çalışıyor. AssetMapper ile bu import’ların uyarlanması gerekecek.

Devam edelim! AssetMapper’ı tam anlamıyla çalıştırmak için son adımları bir sonraki bölümde tamamlayacağız.
